# Большая идея проекта

Это неформальное описание долгосрочной гипотезы, адаптированное для агентов.
Оно не является доказанным claim'ом и должно обновляться после экспериментов.

## 1. Исходная гипотеза

LLM не должны быть такими гигантскими. В них смешивается всё:

- фактологические знания;
- общие способности к рассуждению;
- кэширование решений, как в AlphaGo, где сотни миллионов партий «встроены» в модель;
- широкое покрытие человеческого знания.

Такие LLM могут быть эффективны как «рефлексы» или кристаллизованный интеллект в задачах, на которых они обучены. Но они:

- плохо решают новые задачи;
- не меняются без переобучения;
- хранят в весах знания, которые не нужны для задач других доменов;
- конфликтуют с новыми знаниями, если их надо обновить.

Человек для эффективного мышления не требует такой объём информации. Значит, возможно уменьшить LLM, вынеся часть знаний в **перезаписываемую память**, не ухудшая рассуждение.

Если фактологические знания можно вынести в семантическую память, модель сможет:

- сохранять актуальность знаний без переобучения;
- работать на длинном горизонте;
- меньше конфликтовать между замороженными весами и новыми знаниями;
- поддерживать life-long learning и персонализацию;
- потенциально быть меньше или лучше рассуждать при том же размере.

## 2. Память — не просто лента эмбеддингов

Проблема глубже, чем «расширение контекста». Память должна быть системой представлений, связанных с **произвольными вычислимыми моделями мира**:

- графы;
- пространственные карты;
- структуры событий;
- правила;
- модели объектов и отношений.

LLM не формирует внутри себя такие вычислимые представления; она эмулирует их текстовыми описаниями. Но текст не заменяет вычисления над структурами — например, пространственное внимание или прослеживание пути.

Поэтому конечная система не должна быть просто «замороженная LLM + reader/writer к памяти». Рассуждение должно делаться в терминах вычислимых моделей мира.

## 3. Два направления

### Направление 1: вычислимые представления / world models

`agimaze-predict` добавлял visual workspace и показывал, что LLM может эффективнее решать пространственные задачи. Это не произвольные модели мира, а фиксированное 2D-представление. Его можно развивать:

- разные типы структур;
- обучение выполнять код с созданием структур данных;
- персистентные карты;
- cross-size сравнение малой модели с workspace и большой модели.

Это важно, но не даёт прямого теста гипотезы «LLM не должна быть такой большой».

### Направление 2: малая LLM + перезаписываемая память

`memWMLM` напрямую проверяет гипотезу: малая LLM + память может быть сопоставима с большей LLM.

Там память сначала была примитивной: pooled embedding cells, writer/reader, reset-pair. Это не доказывает устройство памяти, но показывает канал source → memory → application.

## 4. Что показали эксперименты к 2026-11-05

### memWMLM

- Frozen Qwen3-1.7B на bAbI QA1 full-context ≈ 82%; application-only ≈ 0%.
- Pooled memory ≈ 60% train / 55% test; `null_memory` и `shuffled_memory` ≈ 17%.
- LoRA-адаптеры дали лишь ~+2.5 п.п. и оказались практически необходимыми.
- Early injection `[0,1,2,3]` лучше поздней: pooled early ≈ 72.3% test, поздняя + LoRA ≈ 50–60% test.
- QA2: frozen full-context 49.6%; pooled early memory 99.4% train / 81.6% test.
- Шесть задач bAbI: per-task checkpoints лучше mixed; mixed ниже на 5 из 6 тестов.
- 40k QA1 train: 99.7% на unchanged test, но это same-task synthetic extension, не общая память.
- Qwen3-4B на bAbI: не общее улучшение; заметное улучшение только на QA4, небольшое на QA12, небольшое ухудшение на QA11.

### Position-aligned memory и repro

- Pooled «bag» терял позиционную/событийную структуру.
- Position-aligned writer: одна cell на позицию source; число cells = `src_len`.
- Repro Stage A (WikiText-103): 120k train-окон, 3 092 held-out.
- При memory width 2048 repro-loss застревал на ~0.2–0.3 — capacity limit.
- При width 4096 loss падал почти до нуля; eval: exact ~0.2, chain ~82.
- При 2048: exact ~0.005, chain ~16.
- Переход 4096 repro → bAbI дал qa1 0.984, qa4 1.0, qa12 0.964, qa11 0.994; qa2 0.824, qa16 0.894.

### Baseline Qwen на repro

- Qwen3-1.7B full-context, chain: exact 0.08, chain 21.
- Qwen3-4B: exact 0.06, chain 18.
- То есть 4B не лучше на этой задаче; базовый Qwen копирует только короткий префикс.
- Memory 2048 была около chain 16 / exact 0.005 — не выше baseline.
- Memory 4096 — chain 82 / exact 0.2 — выше baseline.

### Selective reproduction

- Memory 4096, trained at `whole_prob 0.3`, eval sentence-only `whole_prob 0.0`:
  - exact 0.42, chain 17;
  - baseline Qwen 1.7B: exact 0.02, chain 2.
- Higher exact на коротких предложениях — в основном target-length effect.
- Selective repro оказался труднее, чем whole-passage, для обеих моделей.
- Training selective loss plateaued/noisy, не полностью converged.
- WikiText грязный: заголовки, `@-@`, обрывы, regex split.

## 5. Уточнения после экспериментов

### 5.1. Эпизодическая память ≠ семантическая память

Эпизодическая память может быть сырой или почти несжатой. Сжатие нужно для стоимости, а не обязательно для способности хранить.

Семантическая память — скорее **умный индекс к эпизодам**: сущности, факты, события, версии, указатели, связи. Главная проблема — **извлечение**, а не сохранение.

### 5.2. Текущая модель — это компетенция использования памяти

Memory sidecar + LoRA учится не только хранить, но и:

- что писать;
- как читать;
- как встраивать в слои;
- как использовать source/память в задаче.

Поэтому улучшение относительно base Qwen — это не чистый эффект памяти, а **память + обученная компетенция её использования**.

### 5.3. Frozen backbone — ограничение эксперимента, не dogma

Полностью замороженная LLM нужна, чтобы отделить память от fine-tuning. Для реальной системы это не обязательно. Если LoRA нужна для использования памяти, claim должен быть: «малая модель + память + малая адаптация», а не «память полностью заменяет обучение».

### 5.4. Нужны задачи, где память действительно нужна

bAbI QA1 lookup-friendly и насыщен. Selective repro проверяет позиционную адресацию, но не multi-hop, temporal, update, contradiction.

Нужны задачи, где ответ требует:

- извлечения из памяти без source в контексте;
- multi-hop;
- temporal order;
- aggregation;
- update/versioning;
- novel instances;
- counterfactual source swap.

## 6. Открытые вопросы и следующие шаги

1. Selective repro — диагностический rung: retrieval vs generation.
2. Repro pause: либо cleaner texts, либо переход к semantic-memory/quiz.
3. Stage B: dense no-reasoning QA по запомненному корпусу.
4. LwF: frozen backbone + память, заполненная одним чтением диалекта; novel-instance; memory vs LoRA/ICL/RAG.
5. Factual knowledge quiz: MMLU/TriviaQA/NQ/SimpleQuestions/Wikidata; отдельный claim о большой фактической памяти.
6. Persistence/update: multi-commit, overwrite, interference.
7. Architecture: hierarchical/segment memory, semantic index, query controller, non-frozen adapters.
8. Model-size ladder: 1.7B+memory vs 1.7B+LoRA vs 3B/7B full-context.

## 7. Главный вывод

Гипотеза «малая LLM + перезаписываемая память ≈ большая LLM» пока **не доказана**. Доказано, что:

- канал source → memory → answer работает;
- позиционная память важна;
- capacity 2048 vs 4096 — реальное ограничение;
- memory+competence может сильно улучшать base Qwen;
- bAbI показывает использование памяти, но в task-specific режиме.

Следующий этап должен проверить **извлечение, обобщение, write-once и обновление**, а не только воспроизведение.
