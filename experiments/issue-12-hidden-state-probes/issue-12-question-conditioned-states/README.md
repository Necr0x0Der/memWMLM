# Состояния после вопроса, до генерации ответа

Отдельный эксперимент по [issue #12](https://github.com/Necr0x0Der/memWMLM/issues/12).
Пошаговый запуск: [RUNBOOK.md](RUNBOOK.md). Он не использует адаптер памяти
из `issue-12-source-free-memory` и не меняет предыдущие эксперименты.

## Вопрос и схема

**Становятся ли пространственные отношения лучше доступны простому linear probe
после предъявления вопроса, ещё до генерации ответа?**

```
ситуация               → одинаковый chat-wrapper → frozen Qwen → hidden states
ситуация + вопрос q    → одинаковый chat-wrapper → frozen Qwen → hidden states
                                                                ↓
                                                probes всех семи отношений
```

Qwen3-4B делает только forward по входному prompt. Используется её базовый
transformer `.model`: LM head и `generate()` не вызываются. Нет сгенерированного
рассуждения, ответа, answer options, teacher forcing, soft prefix или обучения Qwen.
`enable_thinking=False` задаётся обоим chat-шаблонам, но здесь вопрос о внешнем
рассуждении снят отсутствием самой генерации.

Базовый контекст `no_question` содержит ситуацию без вопроса, но с тем же
завершением user-message и assistant generation-prefix. Семь других контекстов
содержат каждый один фиксированный вопрос. После каждого контекста считываем
все семь targets. Отдельно обучаем и выбираем 8 × 7 = **56 linear classifiers**.

## Протокол, зафиксированный до новых test-результатов

- Frozen `Qwen/Qwen3-4B`, revision `1cfa9a7208912126459214e8b04321603b3df60c`.
- Исходный dataset из `issue-12-hidden-state-probes/artifacts/db`, неизменённые
  train/validation/test; условие **none/shuffled**.
- 408/72/96 ситуаций, 17/3/4 независимых abstract-layout групп.
- Восемь контекстов на ситуацию: `no_question` плюс семь вопросов manifest.
  Итого 3264/576/768 forward-примеров, не независимых миров.
- Слои **8, 16, 28, 36**. Индекс 36 — последнее состояние после final norm;
  другие индексы — выход соответствующего transformer-блока.
- `last_token`: последняя непустая позиция **общего assistant-prefix**, а не
  последний токен вопроса/факта. Эта позиция может учитывать весь prompt.
- `mean_pool`: среднее всех непустых позиций prompt, включая chat-wrapper
  и вопрос. Вопрос меняет состав этого среднего; это часть ограничения метода.
- Статистика нормализации и веса probes используют только train.
- L2 = 0.0001 / 0.001; LBFGS max_iter=100; seed=12012 для label controls и bootstrap.
- Для каждой пары «контекст × target» независимо выбираем pooling/layer/L2
  по validation balanced accuracy; ties: обычная accuracy, более сильный L2,
  затем первый кандидат. Всего 16 кандидатов на classifier.
- Все 56 моделей фиксируются **до загрузки test features**. Без refit на train+val.
- Negative control: одна перестановка полных векторов меток между train-группами,
  обучение в выбранной real-label конфигурации. Это не permutation significance test.

## Метрики и интерпретация

Основной результат — матрица 7 вопросов × 7 target-отношений: test balanced
accuracy после вопроса и её разница с соответствующим probe `no_question`.
Для baseline тоже есть полный набор семи classifiers.

Для каждого поданного вопроса отдельно показываем:

1. `asked`: изменение качества на запрошенном target;
2. `inverse`: изменение на обратном отношении, если оно есть;
3. `other_excluding_inverse`: среднее изменение остальных targets;
4. среднее по всем targets и joint exact-target accuracy.

Обратный вопрос не является независимым подтверждением общего состояния:
Mary < John и John < Mary логически связаны. Остальные targets тоже не полностью
независимы; leftmost и транзитивность связывают ответы. Эти семь targets отражают
относительный порядок людей, не полное состояние мира и не точные комнаты.

Парные 95% интервалы: 2000 bootstrap-повторов по test `group_id`, одинаковые
группы для baseline и conditioned. Внутри каждой выборки заново считаются
разности balanced accuracy. Интервалы условны на выбранных probes, не учитывают
training/selection uncertainty и не корректируются на множество сравнений.
Всего четыре test-группы: это exploratory experiment; resampling иногда
пропускает класс, тогда macro считается по присутствующим классам.

Заранее принятая интерпретация:

- рост только `asked` и `inverse` согласуется с доступностью ответа по запросу;
- рост `other_excluding_inverse` в нескольких условиях — более широкий сигнал
  доступности отношений, но сам по себе не доказывает цельное состояние мира;
- отсутствие устойчивого роста означает, что данный readout-протокол не выявил
  улучшения, а не отсутствие состояния в Qwen;
- ни один результат не доказывает причинное использование: для этого нужны
  последующие вмешательства в собственные активации/KV-cache модели.

Это сравнение отдельно оптимизированных readout, не перенос одного classifier
между контекстами. Представление может менять координаты. Дополнительные токены
вопроса дают модели дополнительные позиции вычисления; нейтральный suffix,
сопоставленный по длине, здесь не добавлен. Поэтому эффект нельзя целиком
приписывать именно смыслу вопроса. На просмотренных test-результатах не расширять
сетку, не выбирать «лучший вопрос» и не переименовывать exploratory в confirmatory.

## Артефакты и текущий статус

`extract.py` сохраняет feature shards, точные prompts и manifest с хешами,
chat template, revision, слоями, параметрами и provenance. `probe.py` сохраняет
56 выбранных probes, 56 label-control probes, scores всех кандидатов,
предсказания на test и отчёт с парными разностями.

**Первоначальная проверка реализации, 2026-11-27:** локальный аудит исходного dataset прошёл.
Четыре теста прошли на маленькой случайной Qwen и синтетическом dataset,
включая полный extract→select→test путь. Это проверка реализации, не результат
Qwen3-4B. На этом этапе реальное извлечение и измерение качества ещё не выполнялись.
Протокол записан локально; публикация на GitHub не выполнялась.

**Обновление 2026-11-27:** реальный запуск Qwen3-4B завершён; результаты и аудит
артефактов записаны на английском в [RESULTS.md](RESULTS.md). После вопросов о
парах людей средняя test balanced accuracy probes составила 61,81–70,83%
против 47,62% без вопроса. Это улучшение считываемости до генерации, не
доказательство причинного использования состояния. Следующие проверки:
нейтральное продолжение сопоставимой длины и более разнообразный holdout.
Подмены состояния и адаптер памяти в этот запуск не входят.
